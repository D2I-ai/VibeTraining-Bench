# Pins for the backend tools that execute and grade a task.
#
# These are host-side pins, kept separate from the images: the container definitions
# pin what serves and loads a model (containers/model-stack.txt), while this file pins
# what runs the agent and the verifier. Either moves a score without any model
# changing, so both are pinned exactly rather than with a floor.
#
# Installed on the host by scripts/prepare/install_backend_tools.sh with `uv tool install`
# on a uv-managed Python >= 3.12. This file is the one place to change its version.
#
# harbor executes a task: image lifecycle, the agent's install and run, the memory
# watchdog, and the task's own verifier. Installed from the project fork, pinned to an
# exact commit so the CLI and the VTB_HARBOR_REPO checkout (adapters, harness templates)
# are one source at one version -- a branch name here would drift. Note a leaderboard
# submission is measured with the PyPI release the leaderboard names, not this line.
harbor @ git+https://github.com/StevenLau6/harbor.git@8bbe0424383faf70ab0f040de28713888f0ba364

# Not every host-side dependency is a Python package, so two are named here rather than
# nowhere: fuse-overlayfs, which carries the shared HuggingFace cache into a run, and the
# `user_allow_other` line in /etc/fuse.conf that its allow_root mount needs. Neither is
# pinned -- apt owns their versions and no score depends on them -- but a missing
# fuse-overlayfs is silent on the training path, so it is a setup step: see "Host
# packages" in README.md.
